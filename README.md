# AHA TTS (نسخه سبک Piper) — برای Render

این نسخه به‌جای torch/transformers از **Piper** استفاده می‌کند: یک موتور TTS
بسیار سبک که برای سخت‌افزار کم‌منبع طراحی شده و باید به‌راحتی در ۵۱۲ مگابایت
رم پلن رایگان Render جا بشه.

## جایگزینی کد قبلی
همون‌جوری که قبلاً گفتم:
1. توی ریپوی گیت‌هاب `aha-tts`، فایل‌های زیر رو **کامل جایگزین کن**:
   - `Dockerfile`
   - `requirements.txt`
   - `aha_tts/__init__.py`
   - `aha_tts/engine.py`
   - `aha_tts/server.py`
2. برگرد به Render، منتظر بمون دیپلوی خودکار شروع بشه (یا از Manual Deploy)
3. بعد از سبز شدن، دوباره تست کن:

```bash
curl -X POST https://aha-tts.onrender.com/tts \
  -H "Content-Type: application/json" \
  -d "{\"text\": \"سلام دنیا\"}" \
  --output test.wav
```

اولین درخواست کندتره چون مدل (~۶۰-۷۰ مگابایت) باید دانلود بشه؛ درخواست‌های بعدی سریع‌ان.

## چک کردن مصرف رم
بعد از دیپلوی، این آدرس‌ها رو توی مرورگر باز کن:
- `https://aha-tts.onrender.com/health` — زنده بودن سرور
- `https://aha-tts.onrender.com/memory` — مصرف رم (rss_mb الان، peak_mb بیشترین مصرف). باید همیشه زیر ۵۱۲ باشه.

## نسخه v3
- مدل‌های صوتی موقع build داخل ایمیج دانلود می‌شن (دیگه بعد از خواب/دیپلوی دانلود نمی‌شن)
- سرور موقع بالا اومدن مدل فارسی رو در پس‌زمینه لود می‌کنه؛ `/health` وقتی آماده‌ست `"ready": true` می‌ده
- اگه فایل `aha_tts/server.py` توی گیت‌هابت کلمه‌ی `warm_up` داره، نسخه‌ی v3 آپلود شده

## نسخه v4
- علامت‌های نگارشی (ویرگول، نقطه، علامت سؤال و ...) دیگه به مدل صوتی داده نمی‌شن؛ متن سر هر علامت به عبارت‌های کوتاه شکسته می‌شه، هر عبارت جدا خونده می‌شه و مکث‌ها رو خود موتور می‌ذاره (جلوی نویز/فیش از اون نقطه تا آخر رو می‌گیره)
- اگه فایل `aha_tts/engine.py` توی گیت‌هابت کلمه‌ی `split_into_phrases` داره، نسخه‌ی v4 آپلود شده
